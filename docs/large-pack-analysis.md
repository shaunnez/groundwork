# Large-pack analysis (isolated local branch)

This branch adds a bounded report path for a selected large source pack. It is not deployed to Railway. It preserves existing immutable originals, source versions and older reports. Small assessments keep their existing path. A report with more than 100,000 saved characters or 500 saved units uses `groundwork-segmented-v1`; the extraction contract is `segmented-evidence-v2` and the worker cache version is `worker-v4`.

## Processing and coverage

The API freezes source IDs and hashes at run admission and streams saved units through a preflight. The worker reads up to 100 units per database page. It partitions the exact saved text into segments at line or whitespace boundaries without dropping characters. PDF pages, DOCX paragraphs and tables, and XLSX sheets inherit their reader location; spreadsheet segments add a locatable cell range where cell markers exist. A segment is at most 12,000 UTF-8 bytes, or 2,000 for a sheet, and a batch prompt at most 24,000 bytes. The worker also checks each complete model input, including schema and system prompt, against a conservative 64,000-token upper bound inferred from UTF-8 bytes. Claude output remains capped at 12,000 tokens. A segment that cannot fit fails explicitly. This bounds transport size; it is not a model context guarantee.

Each batch requests one outcome for every segment, including an empty outcome. The validator reconciles input IDs with output IDs, checks schema and quote text against the saved segment, and prevents proposed DOCX insertion/deletion wording from being labelled operative. The durable `analysis_segments` ledger records pending, processed or failed state and a reason. Structured findings and requirement occurrences are stored in `analysis_items` with source, unit, segment, location, exact quote and revision state. The API pages the full ledger at `/api/runs/:id/analysis-items`. Report requirements show up to 100 distinct examples and explicitly link to the full ledger; duplicates at different source locations remain inspectable. A processed segment proves an outcome was recorded, not that the model found every semantically relevant statement.

The report synthesis selects up to 12 findings per source and 180 overall, then trims the selected list to a 32,000-byte synthesis prompt. Omitted findings stay in the ledger and their count is visible. Synthesis and support review can cite only selected, saved units; report quotes are validated against the original saved unit, then separately reviewed for support. The source inventory, reader gaps, exclusions and selection limit are retained in the report. This is bounded summarisation rather than an exhaustive representation of every extracted finding in the report narrative.

Run stages and provider receipts remain durable. Repeated processing skips fully processed batches; a recorded model stage can be reused without paying for a completed call again. Inputs include source and segment hashes, extraction method, prompt/schema hashes, model and transport version. Interrupted or uncertain provider calls keep their existing reconciliation gate. Cancellation and lease checks run between batches and before database publication. The configured allowance defaults to 96 model calls and 180 minutes for a segmented run; `analysisMaxModelCalls` in private config or `GROUNDWORK_ANALYSIS_MAX_MODEL_CALLS`, and `analysisRunMinutes` or `GROUNDWORK_ANALYSIS_RUN_MINUTES`, provide bounded operator overrides. Preflight adds six calls for synthesis, verification and possible corrections, then blocks admission above the call allowance. The worker checks the allowance again before each new provider call. Historical successful receipts supply an API-equivalent estimate; it is not an actual subscription bill.

## Local qualification, 23 September 2026

`GROUNDWORK_CONFIG=/Users/shaun/projects/groundwork/.local-groundwork/config.json node --import tsx scripts/preflight-large-pack.ts --rfx=34995788` verifies each selected original against the private manifest and stored source hash, then writes a private receipt under this worktree's ignored `.local-groundwork/receipts/`. It does not make a model call or print document text.

The local mirror has 13 current originals, all 13 checksum and size reconciled, plus the public notice source. It has 3,843 extracted units and 698,162 saved characters. The previous eight-candidate path would have needed roughly 481 requirement calls before assessment and support review; the former readiness guard rejected selected text above 160,000 characters. The new preflight partitions readable text into 3,886 segments and 78 bounded batches, with a 23,999-byte peak batch prompt. It estimates 84 total calls under the default 96-call allowance and $16.57 in historical API-equivalent usage. Preflight itself took 367 ms and increased process RSS by about 67 MB in this run. These are local measurements, not a live model-run receipt.

Four Office sources retain partial reader outcomes: three DOCX files, including draft contract revision or embedded-image limits, and the XLSX pricing schedule with visual material. Existing saved DOCX units were extracted by the older `docx-structure-v1` reader. Therefore this branch does **not** claim a complete RFP reassessment for RFx 34995788 and did not start a live model run. The selected-pack reader must resolve or explicitly scope each gap, and the DOCX source versions must be re-admitted with revision-aware reader output before proposed wording can be evaluated as such. Original drawings remain retained; engineering interpretation is outside scope. Formula and cell text stays attached to sheet locations where the reader extracted it; visual workbook material is still a named gap.

The deterministic synthetic test uses 80 documents and 7,508,530 characters, more than ten times the current bridgeworks saved text. It runs a fake model only and recorded all 640 segments over 560 batches, with a 23,686-byte peak prompt, 40,255,488-byte RSS increase and 2,243 ms elapsed in the passing run. It checks resume without another model invocation. This qualifies accounting and process bounds, not model extraction quality or hosted throughput. A real run of that size would exceed the default call allowance and must stop at preflight for explicit scoping or budget review. Future hosted use requires the additive schema migration, worker deployment, complete reader qualification and a separately approved bounded live acceptance run; no Railway configuration or credentials are changed here.
